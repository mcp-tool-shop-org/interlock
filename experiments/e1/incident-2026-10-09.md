# E1 incident 2026-10-09 — NPU device loss at nomic-npu-l1024-b8

Session: publisher-e1-open-2026-10-09, run_id e1-intel-2026-10-09, spec
experiments/e1/spec.yaml at blob 29209e5cbe04744ab1bc7bcd09e1be144e2f1e79
(54 arms, interleaved). NPU + iGPU only, quiet CPU window, no grant, no
Ollama. The session was logged with the Publisher at start.

## What happened

The run died at arm nomic-npu-l1024-b8 (nomic-embed-text-v1.5, NPU,
8x1024 static shape) with `ZE_RESULT_ERROR_DEVICE_LOST` — a Level Zero
device hung/reset raised by the driver mid-measurement. This is not the
adapter's 60 s per-call hang bound (a stuck call we can stop observing);
the driver reset the device out from under the call.

Per the hang protocol: the process was ended, nothing was retried, and the
run wrote no receipts (the harness writes at run end, and the failed step
stopped the sequence), so the table was untouched.

## Evidence

- NPU driver 32.0.100.5540 (Intel), dated 2026-08-19.
- Windows System event log, scanned 16:15–17:10 local on 2026-10-09: no
  entry for the reset. Only WindowsUpdate and Kernel-General informational
  noise in the window. %SystemRoot%\LiveKernelReports is empty. Finding:
  an L0 device reset is OS-silent on this stack — the ZE result code is
  the only witness.
- After the reset the NPU enumerates normally; the next process lists it
  in `available_devices`. The loss does not persist across processes.
- The same 8x1024 shape ran fine for bge-base and bge-small earlier in the
  same session, so this is not a blanket batch-8 failure; one arm's loss
  is one data point.

## What changed because of it

R&D's ruling (option b, 2026-10-09):

1. The adapter classifies a device loss as a recorded result —
   `resolved.outcome` `device_lost` with no timing fields, like an
   unsupported-length row, and `not run` for the device's remaining steps —
   instead of dying with the run. (#17)
2. Every NPU arm with batch > 1 moved to the tail run
   experiments/e1/spec-b8tail.yaml (this directory), which runs after the
   main run's receipts are written, in the same booked session.
3. No NPU session — E1's rerun, E2's NPU arms, E3 — until the Publisher's
   NPU health check reports. This session's end line to the Publisher said
   so.

The analysis is unchanged: B_reuse vs T = 100 on batch-1 rows, the
minimum-cosine parity guard per arm against the same model's CPU batch-1
reference at the same length, and the longest-bucket length finding.
