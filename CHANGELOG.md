## [1.0.0] - 2026-10-25

The first release since 0.2.0. There was no separate 0.3.0 release; its changes ship in 1.0.0. From 1.0, versions follow semantic versioning.

### Security

- `LinuxOllamaServer` and `run_spec` (`seams["host"]`) refuse any non-loopback Ollama host before starting `ollama serve`, accepting only `127.0.0.1:<port>`, `[::1]:<port>`, or `localhost:<port>` with an ASCII port when `localhost` resolves exclusively to loopback, re-checking the host when the server starts, and keeping the shared ports `11434` and `11490` refused.
- Remote rows now refuse an unhashed account token (`account:<id>`, `user=<id>`, `owner:<id>`, `uid:<id>`, and related prefixes followed by `:` or `=`, with optional whitespace around the separator, and an identifier) anywhere in any string value or dict key at any depth, alongside the existing `sha256:<64-hex>` check on account and GGUF-source fields.

### Fixed

- C2 (`linux-cuda`) model sources, quant labels, tokenizer-exact throughput inputs, and live source verification: every entry in `experiments/c2-{fill-card,generate,throughput}/spec.yaml` now names a real, verified source (`ollama_tag` with its Ollama registry manifest digest in `revision_or_digest`, or `gguf` with its Hugging Face repo, 40-hex commit `revision`, `file`, and 64-hex `sha256`), including the Ollama library builds for Gemma 4 31B (`gemma4:31b-it-q4_K_M`, `gemma4:31b-it-q8_0`, and `gemma4:31b-it-bf16` while keeping `model` as the role-set `sha256:<64-hex>` hash and `Q6_K` as `no published Q6_K build`). Every pre-registered `load_refused` cell states a measured `failure_reason` (layer MiB vs card VRAM/0.90 abort ceiling, `no published Q6_K build`, or `out of scope: stock Ollama does not serve <task>`). Entries that pull `fp16` builds (`qwen3:8b-fp16`, `phi3.5:3.8b-mini-instruct-fp16`, and all C2 throughput models) declare `quant: FP16`, while true `bf16` builds (`gemma4:31b-it-bf16`, `muse-glimmer:30b-bf16`) declare `quant: BF16`. Throughput (`batch-ladder`) inputs are built per model with each model's own tokenizer at its pinned Hugging Face revision to exact `128`-token and `510`-token lengths (staying within `max_position_embeddings: 512` after special tokens on `bge-base-en-v1.5` and `nli-deberta-v3-base`) in the committed fixture `experiments/c2-throughput/inputs.json` (`sha256: 48f5905ddcb24f66d9a6cd59ff2376e8766db3f8ebd4aa1e141f2fb290332966`). `interlock c2-sources <spec> [--json] [--verify-live]` resolves every entry and, with `--verify-live`, queries `registry.ollama.ai` and `huggingface.co` to verify every source, manifest/LFS digest, config `file_type` quant label, refusal condition, and upstream `tokenizer.json` digest.

### Docs

- The README and handbook say what is new in 1.0.0, and drop the prototype and 0.x wording: from 1.0, a change that breaks the CLI, the receipt format or the spec format comes with a new major version, and the latest 1.x release receives security fixes. The landing badge says v1.0.0. The handbook's experiments page has a C2 section for the remote Colab specs, and the threat model and security page cover the Linux CUDA path and the remote importer.
- `CONTRIBUTORS.md` credits the AI seats that wrote the code: Grok ("Written with Grok", xAI), Kimi and Claude. The README links it.

### Added

- Remote Colab device identity (`colab:A100-40`, `colab:A100-80`, `colab:L4`, `colab:T4`, `colab:G4`) in `routing-row.schema.json`, `devices.py`, and `receipt.py`, recording `provider`, `card`, `vram_mib`, numeric `driver_version` and `cuda_version`, and a zone `pool` string while refusing unhashed account identifiers across every string field of `remote_device` and `ggufRepo`/`gguf_source`, and keeping remote rows separate from rig rows.
- Linux CUDA measuring path (`src/interlock/harness/linux_cuda.py`) wired into `interlock run` (`--dry-run` and live `run_spec` for `platform: linux-cuda`): reads residency from `/api/ps` and VRAM/driver/CUDA from NVML or `nvidia-smi --query-gpu` with card-VRAM range checks and no Windows counters, records `engine_version` from `/api/version` (or `unrecorded` on pre-server failure), records failed shapes (`oom`, `load_refused`, `timeout`, `ctx_exceeded`) as capability rows, and provides the `fill-card` (with 2048-token grid bisection), `generate-ladder` (512..32k at concurrencies 1, 4, 8), and `batch-ladder` (`embed`/`rerank`/`nli` at batches 1, 8, 32) specs under `experiments/c2-fill-card/`, `experiments/c2-generate/`, and `experiments/c2-throughput/`.
- Remote window receipt importer (`src/interlock/importers/remote.py`, `interlock import --remote-window <path>`) preserving every repeat slot in `artifacts.slots`, `interlock table --device colab:<card>` (and `colab:*`), and opt-in remote routing (`interlock route --allow-remote` / `--device colab:<card>`) that filters remote rows before the outcome loop on rig requests, marks remote winners with `remote: true` and `remote_device`, and names measured failure reasons on refusal.

## [0.2.0] - 2026-10-14

- `--trace relay|events`: an opt-in **debug** tracer for interlock runs, built on NeMo Relay 0.10.1 (optional `relay` extra; the base install imports nothing from Relay). Every adapter request is counted, the card guard's included; spans close per slot; prompts are blanked, and only one Relay sink may be live in a process. A traced run is debug-only: its rows are marked descriptive and never reach `table/routing.jsonl`, and a name whose traced run left a trace without a receipt is refused. Tracing is never for counted runs: the pre-registered stage 1 trial (rnd `experiments/interlock-relay/`) measured about 0.27-0.34 ms of client time per traced call on a cold CPU, over its 0.5 ms per-slot budget. With `--trace off`, speed fields and routes are unchanged; untraced 5090 runs now count the card guard's request and the companion's stop in `artifacts`, which shifts call ids by one.
- The README and its translations show a PyPI badge for `mcptoolshop-interlock`, now that 0.1.0 is published.

## [0.1.0] - 2026-10-14

Prototype advisory router for one rig. It suggests a model, an engine and a device from measured receipts, and it does not serve traffic. It is a prototype, not a beta. The first release on PyPI, as `mcptoolshop-interlock`, with SLSA provenance on the GitHub release assets.

- Dependabot opens a grouped pull request monthly for the uv lock, the docs-site npm lock, and GitHub Actions, at most three open per ecosystem. A coverage-guided fuzz target feeds bytes to the receipt-line reader (`check_tree`) and the spec loader (`load_spec`). A published GitHub release attaches the wheel, the sdist, and a SLSA provenance file.

- CONTRIBUTING.md says how to report a bug, where a security report goes, and the bar for a pull request. CI runs `ruff check` (0.17.0; rules E, F, W, B, I, UP, and S) on every change and fails on any finding.

- The Ollama supervisor stops a listener only when port 11434 has exactly one, and only when that process is the Ollama install `serve` starts. Zero listeners, two or more, a different executable, or a path that cannot be read refuses and stops nothing. The restart record keeps the pid and the path that was checked. Port 11490 is not queried on that path. E4b refuses a dirty worktree at the start, before any device, for the block and the pilot. E4b reads flash attention and the KV cache type from the model's first-load lines, and keeps the environment value as `config_flash_attention`. A missing load line refuses before any measured slot. The committed E4b receipts are unchanged. (R&D after #83 and #88, 2026-10-13)

- OpenSSF Scorecard. `.github/workflows/scorecard.yml` runs weekly, on demand, and when branch protection changes. It publishes the result and uploads the SARIF file. The README and its translations show the Scorecard badge. CI and the release workflow now set a top-level read-only token permission. The workflow does not run on push.

- E5 waits until the pinned adapter's dedicated reading is back within `settle_tolerance_mib` (512) of the idle reading taken before the model's first load after any confirm count, whoever unloads the runner (`keep_alive` 0 included), and only then sends the measured request. That reading is the call's pre-call reading and it carries `count_ran`. `unloaded` still means the harness unloaded. The reading taken before the count is the pre-count reading. The resident floor applies only where no count comes before the call. A card that does not settle makes the model inconclusive. A load, which does not count, keeps the resident-floor wait. (spec amendment 2026-10-13, after #110)

- Fixed: an E5 window whose card crosses `abort_mib` after `observe` has checked the sampler, and before that call's `cover` returns, is an abort (`card memory reached abort_mib`). It is not kept: no measured point, no resident mark, and the model stays unloaded. The stop label is `margin`, for a load and for a confirm. Found live 2026-10-13 on the granite check. The spec already says abort and unload at 30500. No spec amendment.

- Slot probe (`instrument_perturbs_measurement`): during a measured call, `open()` and the 1 s loop read only total CPU, RAM and the disk counter. After the call, and only when that slot's CPU max is over 30%, two snapshots a second apart rank other processes by the user-plus-system CPU time they used between the snapshots. The receipt records that list as `top_after_call`. pid 0 is left out. The run's own process tree is left out. pid 4 stays. An idle slot does not take the snapshots.

- E5 waits until the pinned adapter's dedicated reading is back within `settle_tolerance_mib` (512) of the idle reading taken before the model's first load after a confirm's count unloads, and only then sends the measured request. That reading is the call's pre-call reading. The reading taken before the count is the pre-count reading. The resident floor applies only where no count unload comes before the call. A card that does not settle makes the model inconclusive: `max_resident_ctx` stays null, and that window is not a margin ceiling. (spec amendment 2026-10-13, after the review of ce7b31e on #107)

- E5 unloads a resident model before a measured load or confirm whose `num_ctx` differs from that runner, then waits until the pinned adapter's dedicated reading is within `settle_tolerance_mib` (512) of the idle reading taken before the model's first load. The call loads at the new `num_ctx` only after that settle. A call at the same `num_ctx` keeps the resident-floor wait. A card that does not return to idle within `settle_timeout_s` (30) refuses that call, and the measurement is not kept. Each pre-call reading records the resident runner's `num_ctx` (null when nothing is resident) and whether that unload happened. (spec amendment 2026-10-13, after the live smoke on #107)

- E5's confirm walk labels a measured abort as `margin`, including when the search had stopped on `predicted_over`. A spill keeps the label the search already set, and the cap stays `max_ctx`. Before each measured load or confirm, the run waits until the pinned adapter's dedicated reading is within `settle_tolerance_mib` (512) of the expected pre-call level and records that reading. Between models and after an unload, that level is the idle baseline. Within a model the search keeps the model resident, so the level is the resident floor. A card that does not settle within `settle_timeout_s` (30) refuses that call, and the measurement is not kept. With `num_predict` 1, `decode_tok_s` and `latency.throughput` are null and carry a reason, so a one-token generate is not reported as a decode rate. (spec amendment 2026-10-13, after e5-2026-10-13c)

- OpenVINO NLI and rerank steps take the model's flat logit row as their output. Pooling `none` used to expect one row per position, so a real cross-encoder failed with "'float' object is not iterable" (E4's sixth live run, iGPU, 2026-10-12). The fakes had returned per-position rows.
- The Ollama prompt fit estimates the seed repeats from the seed's own count, then trims only past the longest prefix known to be short. It used to add one seed per count, which took thousands of counts at a 118k-token target: E5's first live run spent over 30 minutes on one model without a row.
- The Ollama token count asks for one completion token, never zero. Ollama 0.35.1 reads `num_predict` 0 as no limit and generates until the context fills. E4's first live run (2026-10-11) sat at full card power for 12 minutes without writing a row. The zero-then-retry path is gone.

### Earlier development (before the first release)

Advisory only. `switchyard route` refuses when no measured row meets the constraints. It does not fall back, serve traffic, read a ledger, or call offrig. The bound is the conservative end of the measured spread, never a median. A parity miss is excluded. `thinking off` matches only off. `thinking on` matches any recorded thinking level, and the decision keeps that level.

#### Phase 0

Scaffold: the device allow-list, the grant and session guards, receipt validation, and CI with a coverage floor of 90. The iGPU is the Intel integrated GPU.

#### Phase 1

The routing table is built from pinned receipts.

#### Phase 2

The harness runs a committed spec and writes receipts. A rejected compile, a hang, and a lost device are recorded, and they are not speed.

#### Phase 3

E1, E2, and E3 measure embed and small-model generation on CPU, the Intel iGPU, and the NPU. A 5090 reference anchors Qwen3-8B.

#### Phase 4

`switchyard route` chooses from that table. The choice is one pure function of the rows and the request. When the set is empty, the command exits 1 and names the constraint. It does not guess.
